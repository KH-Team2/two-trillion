## 왜 필요한가

화면은 프론트 안의 통계 파일(`src/data/statistics/group-stat-2024.json`)에서 브라우저 입력값(성별 · 생년월일 · 급여)으로 그룹을 찾고 있었습니다. 서버에 저장된 회원 정보와 소득으로 그룹을 찾도록 서버 조회로 바꿨습니다.

## 호출 흐름

1. 화면이 대시보드나 통계 화면(`stats`)으로 바뀌면 `fetchGroupStats(data.taxYear)` → `GET /api/group-stats/{taxYear}` (의존 배열 `[page, data.taxYear]`).
2. 응답 `{ taxYear, ageGroup, salaryGroup }`을 `groupStats`에 넣습니다. 실패하면 `null`로 비웁니다.
3. 화면의 귀속 연도와 응답의 `taxYear`가 같을 때만 `serverGroups`로 넘깁니다. 연도를 바꾼 직후 이전 연도 통계가 잠깐 보이는 것을 막으려고요.
4. `groupComparison(data, result, serverGroups, isDemo)`가 `serverRow()`로 서버 칸 이름(`groupLabel` 등)을 통계 파일의 칸 이름(`GROUP_LABEL` 등)으로 바꿔서 기존 그리기 코드를 그대로 씁니다.

- 서버 값이 있으면 서버 것만, 없으면 통계 파일 것만 씁니다. 서버가 못 찾은 그룹(null)을 화면 입력값으로 대신 채우지 않습니다. 두 쪽은 인원 기준과 그룹 이름이 달라서, 섞으면 「서버가 찾았다」는 문구와 실제가 달라지기 때문입니다.
- 통계 화면은 「나의 계산 결과」 막대에 서버 계산 결과(`result`)를 쓰고, 없을 때만 체험용 계산을 씁니다. 그래서 저장된 계산 결과 조회(`fetchLatestCalculation`)도 통계 화면에서 부릅니다.

## 화면에서 달라지는 것

| 볼 곳 | 서버 값 | 서버에 연결 안 됨 |

| 안내 문구 | 서버(DB)에 저장된 통계에서 내가 속한 집단을 조회했습니다 | 서버에 연결되지 않아 화면에 보관한 통계로 표시합니다 |

## 화면 확인하며 고친 것 (11/13)

- 대시보드에 들어올 때 통계 조회가 두 번 나가던 것: 의존 배열의 `calcResult`를 뺌. 계산은 입력 화면에서 하고 끝나면 대시보드로 넘어오므로, 화면이 바뀔 때 다시 부르면 새 총급여가 반영됩니다.
- 통계 화면에서 바로 새로고침하면 「나의 계산 결과」가 데모 숫자로 나오던 것: 저장된 계산 결과를 대시보드에서만 불러오고 있었음 → 통계 화면에서도 불러오게 바꿈.

## 아직 남은 것

- 대시보드 카드의 「성별」 칸은 서버 값이 아니라 브라우저 입력값입니다. 로그인이 서버와 연결되기 전까지는 서버가 찾은 그룹과 다를 수 있습니다.
