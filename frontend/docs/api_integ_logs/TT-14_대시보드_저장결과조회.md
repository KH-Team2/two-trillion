# TT-14 결과 대시보드 — 저장된 계산 결과 조회 화면 API 연동 상세 기록

- 요약(어떤 화면이 어떤 API를 어떤 순서로 부르는지)은 `../API_INTEGRATION.md`에 있습니다. 이 파일은 그 상세 기록입니다.
- 대상: F-06-01(결과 대시보드)
- 관련 코드: `src/api/calculation-service.js`의 `fetchLatestCalculation()` · `src/App.jsx`의 대시보드 진입 `useEffect` · `src/api/calculation-contract.js`의 `parseCalculationResult()`
- 오류 코드 전체 표와 응답 봉투 규칙의 원본은 `backend/docs/api-rules.md`입니다. 여기에는 이 화면이 실제로 만나는 오류와 화면 동작만 적습니다.
- 작업 이력: 11/12 조회 API 추가(백엔드) · 대시보드 진입 시 조회 연결

## 왜 필요한가

계산 결과는 계산 직후의 응답과 브라우저 저장(`histories`)에만 있었습니다. 그래서 다른 브라우저로 들어오거나 브라우저 저장이 지워지면, DB에 저장된 결과가 있어도 대시보드는 체험용 계산을 보여 줬습니다. 대시보드에 들어올 때 서버에 저장된 결과를 읽어 오도록 했습니다.

## 호출 흐름

`App.jsx`의 `useEffect`(지켜보는 값: `page` · `data.taxYear` · `calcResult`)가 아래 순서로 동작합니다.

1. 화면이 대시보드가 아니면 아무것도 하지 않습니다.
2. 그 귀속 연도의 서버 결과(`calcResult`)가 이미 있으면 부르지 않습니다. 방금 계산한 결과나 브라우저 저장에서 이어 온 결과가 그대로 쓰입니다.
3. 없으면 `fetchLatestCalculation(data.taxYear)` → `GET /api/calculations/{taxYear}` (본문 없음).
4. 응답을 `parseCalculationResult()`로 검사한 뒤 `setCalcResult`에 넣습니다. 계산 직후와 같은 상태에 넣으므로 대시보드는 `result` · `isDemo={false}`로 같은 코드가 그립니다.

- 응답 모양은 계산(`POST /api/calculations/{taxYear}`)과 같습니다 (`predictionId` · 세액 · 환급액 · `details[]`).
- 서버는 본인의 그 연도 결과 중 가장 최근 1건만 돌려줍니다. 시뮬레이션 결과는 빠집니다.
- 응답이 오기 전에 화면을 떠나거나 귀속 연도를 바꾸면, 늦게 도착한 응답은 버립니다 (`ignore`).
- 결과가 들어오면 2번 조건에 걸려 다시 부르지 않습니다. 대시보드 진입 한 번에 요청은 한 번입니다.

## 실패했을 때

| 경우 | 상태 · error | 화면 동작 |
| --- | --- | --- |
| 그 연도에 계산한 적이 없음 | 404 `NOT_FOUND` | 알림 없이 지금 화면 그대로 (체험용 계산 표시) |
| 서버에 연결할 수 없음 | `OFFLINE` | 알림 없이 지금 화면 그대로 |
| 그 밖의 서버 오류 | 5xx 등 | 알림 없이 지금 화면 그대로 |

계산 버튼(`App.calculate()`)은 실패하면 서버 문구를 알림으로 띄우지만, 이 조회는 띄우지 않습니다. 사용자가 시킨 동작이 아니라 화면이 스스로 확인하는 것이고, 계산한 적이 없는 것은 오류가 아니기 때문입니다.
