# TT-105 조건 변경 시뮬레이션 · 결과 이력 화면 API 연동 상세 기록

- 요약은 `../API_INTEGRATION.md`의 「조건 변경 시뮬레이션 · 결과 이력」에 있습니다. 이 파일은 그 상세 기록입니다.
- 대상: F-04-01(조건 변경 시뮬레이션) · F-04-02(결과 이력)
- 관련 코드: `src/api/prediction-service.js` · `src/App.jsx`의 `startSim()` · `calculate()` · `src/pages/simulation/SimulationPage.jsx`
- 서버 API: `POST /api/simulations/{taxYear}` · `GET /api/predictions?year=` · `GET /api/predictions/{id}` (PR #27)
- 오류 코드 전체 표와 응답 봉투 규칙의 원본은 `backend/docs/api-rules.md`입니다.

## 왜 필요한가

비교 화면은 기존 · 변경 후 모두 브라우저 체험 계산(`taxService.calculate`)이었고, 「시뮬레이션 저장」은 브라우저에만 남았습니다. 시뮬레이션 API가 바꾼 조건으로 계산 서버를 불러 시나리오로 저장하므로(INCOME · EXPENSE는 그대로), 화면을 이 API에 연결했습니다.

## 호출 흐름

1. 대시보드 「시뮬레이션」 → `startSim()`: 입력값 · 거래를 복사하고, 지금 보이는 서버 계산 결과를 기준 결과(`baseResult`)로 잡습니다.
2. 가상 입력 화면에서 계산 → `calculate()`(시뮬레이션 모드)
   - 기준 결과 번호가 없거나 귀속 연도가 다르면 요청하지 않고 안내를 띄웁니다. 개발 서버에서만 체험용 비교로 넘어갑니다.
   - `simulate(d, tx, baseId)` → `POST /api/simulations/{taxYear}`
3. 응답을 `parseCalculationResult()`로 검사한 뒤 `simResult`에 넣고 비교 화면으로 갑니다.
4. 비교 화면: 기존 = `baseResult`, 변경 후 = `simResult` (둘 다 서버 값). 서버 결과가 없으면 둘 다 체험용 계산입니다.
5. 비교 화면 아래 「결과 이력」: `GET /api/predictions?year=` (새 시나리오가 저장되면 다시 불러옴) · 「열기」 → `GET /api/predictions/{id}` → 항목별 내역 표시

## 요청 본문 (SimulationRequestDTO)

| 이름 | 화면 값 | 만드는 곳 |
| --- | --- | --- |
| `basePredictionId` | 기준 결과의 `predictionId` | `App.jsx` `baseResult` |
| `scenarioName` | 시나리오 이름 (비면 「조건 변경 시나리오」 · 16자까지) | `simulationRequest()` |
| `income` | 소득 입력 전부 | `incomeRequest()` 재사용 (소득 저장과 같은 검사) |
| `homelessHeadYn` | 주택 「무주택」 + 세대주 「예」 → Y · 「아니요」 또는 「주택 보유」 → N · 「확인 필요」는 막음 | `homelessHeadYn()` |
| `cardSpends` | 업로드 거래(그 연도 · 집계 포함 · 결제수단 확인된 것) + 가상 추가액을 분류 × 결제수단별로 합침 | `cardSpends()` |

- 분류 번호: 1 일반 · 2 대중교통 · 3 전통시장 · 4 문화체육 · 5 공제 대상 아님 (SPEND_CATEGORY)
- 결제수단: CREDIT · CHECK · CASH

## 실패했을 때

| 경우 | 상태 · error | 화면 동작 |
| --- | --- | --- |
| 기준 결과 없음(계산 전 · 저장 꺼짐) | 요청 안 함 | 「먼저 기존 정보로 계산해 주세요」 · 입력 화면에 머묾 (개발 서버는 체험용 비교) |
| 입력 오류(감면 · 세대주 「확인 필요」 · 이름 16자 초과 등) | 요청 안 함 / 400 | 문구 알림 · 입력 화면에 머묾 |
| 기준 결과가 남의 것 · 다른 연도 | 404 `NOT_FOUND` | 서버 문구 알림 · 입력 화면에 머묾 |
| 서버에 연결할 수 없음 | `OFFLINE` | 배포본: 안내만 · 개발 서버: 체험용 비교 |
| 결과 이력 불러오기 실패 | 모든 오류 | 이력 칸에 문구 표시 (비교 결과는 그대로) |

## 화면 변경 (11/16)

- 비교 화면 옆 AI 절세 가이드(상담 칸)를 뺐어요. 상담 칸이 체험용 계산으로 문장을 만들어서 서버 결과와 다른 숫자가 같이 보였어요. 챗봇은 세법 용어 설명용으로 줄어서(동석님 확인) 시뮬레이션 숫자와 연결하지 않아요.

## 알려진 한계

- 카드 사용액: 기존 결과는 서버 `EXPENSE`로, 시뮬레이션은 화면의 업로드 거래 + 가상 추가액으로 계산합니다. 업로드 내역이 `EXPENSE`에 저장되기 전에는 조건을 바꾸지 않아도 카드 공제가 다르게 나올 수 있습니다.
- 서버 저장 설정(`prediction.save-enabled`)이 꺼져 있으면 계산 결과에 `predictionId`가 없어 시뮬레이션을 시작할 수 없습니다.
- 브라우저에만 저장된 예전 시나리오(`saved`)는 마이페이지에 그대로 남습니다.
