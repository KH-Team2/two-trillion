# 0004. 로그인 방식: JWT 액세스 토큰 하나 (리프레시 토큰 없음)

- 날짜: 2026-11-16 · 상태: 적용 (화면 연결 전)
- 관련 기능: F-01-02 로그인 · 로그아웃
- 관련 코드: `common/config/SecurityConfig.java` (주소별 규칙 · JWT 필터 · 401/403 응답) · `common/service/TokenService.java` (발급 · 검사 · 로그아웃 목록) · `member/service/LoginService.java` · `member/controller/MemberController.java` · `common/mapper/AccessLogMapper.java`

## 결정

1. **로그인 방식: 토큰(JWT)**: 세션은 쓰지 않아요.
   - 토큰에는 회원번호(`sub`) · `loginId` · `role` · 토큰 번호(`jti`) · 만료 시각이 들어가요.
   - 서명은 HS256이고, 비밀키는 `.env`의 `JWT_SECRET`이에요. 32바이트보다 짧거나 없으면 서버가 켜지지 않아요.
2. **리프레시 토큰은 쓰지 않아요**: 액세스 토큰 하나만 쓰고, 유효 시간은 2시간이에요(`JWT_EXPIRATION`). 만료되면 다시 로그인해요.
3. **토큰은 DB에 저장하지 않아요**: 서버는 서명만 확인하면 돼요. 그래서 ERD에 토큰 테이블이 없어도 돼요.
4. **로그아웃은 서버 메모리의 무효 목록으로 처리해요**: 토큰 번호를 그 토큰의 만료 시각까지 보관해요. 서버를 재시작하면 목록이 사라져요.
5. **화면 보관은 localStorage에 하고, 요청 헤더 `Authorization: Bearer <토큰>`으로 보내요.** 연결은 화면 작업 단계에서 해요.
6. **회원번호 전달 방식**: 필터가 로그인 정보의 principal에 회원번호(`Long`)를 넣어요.
   - Controller는 `@AuthenticationPrincipal Long memberId`로 받아요.
   - 개발용 `X-Member-Id` 헤더를 이 방식으로 바꿔요.
7. **로그인 잠금**: 5번째 실패하면 10분 동안 잠가요. `LOGIN_LOCK_ENABLED`로 켜고 끌 수 있고, 기본값은 켜짐이에요.
   - 잠금 시각은 DB 시각(`SYSDATE`)으로 저장하고 비교해요.
8. **로그인 메서드에는 `@Transactional`을 붙이지 않아요**: 실패하면 예외를 던지므로, 트랜잭션 안이면 실패 기록(ACCESS_LOG · 실패 횟수)까지 같이 취소되기 때문이에요.

## 이유

- **리프레시 토큰을 빼는 이유**
  - 화면이 localStorage에 보관하면 두 토큰이 같은 곳에 놓여요. 하나를 훔치면 둘 다 훔치는 셈이라 나눈 의미가 없어요.
  - 만들 것이 크게 늘어나요: 재발급 API, 401을 받으면 재발급 후 다시 요청하기, 서버 쪽 폐기 기록.
  - 소득 입력 → 계산 → 결과 확인을 한 번에 끝내는 서비스라 2시간이면 충분해요.
- **로그아웃을 메모리 목록으로 하는 이유**: ERD에 저장 테이블이 없고 DB 변경은 금지예요. 이메일 인증과 같은 방식이에요.
- **CSRF 보호를 끄는 이유**: 쿠키를 쓰지 않고 헤더로만 토큰을 받아요. 브라우저가 헤더를 자동으로 붙이지 않으므로 CSRF 공격이 성립하지 않아요.

## 알고 쓸 것 (단점)

- 서버를 재시작하면, 로그아웃한 토큰이 남은 유효 시간(최대 2시간) 동안 다시 통해요. 화면은 이미 토큰을 지웠으므로, 문제가 되는 건 토큰을 따로 복사해 둔 경우뿐이에요.
- 탈퇴하거나 역할이 바뀌어도, 이미 발급한 토큰은 만료될 때까지 예전 정보로 통해요. 탈퇴 기능을 만들 때 탈퇴 API에서 그 토큰도 로그아웃 처리해요.
- 화면에 남의 스크립트가 끼어들면(XSS) localStorage의 토큰을 읽을 수 있어요. React가 기본으로 막아 주고, `dangerouslySetInnerHTML`은 차트 CSS 한 곳뿐이에요.

## 확인 필요

- `ACCESS_LOG.LOG_ID` 시퀀스가 생기면 MAX + 1 방식을 교체해요 (decisions/0003과 같아요).
- 불편하다는 의견이 많으면 리프레시 토큰을 추가할지 다시 판단해요. 이때 httpOnly 쿠키와 CSRF 대비가 같이 필요해요.
