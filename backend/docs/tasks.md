# 남은 작업 (backend · 세액 계산·진단 파트)

보안 점검(11/06 · 11/09 재점검)에서 나온 것 중 아직 안 한 항목과 이유.

| 항목 | 상태 | 이유 · 언제 |
|---|---|---|
| 회원번호를 `X-Member-Id` 헤더 대신 로그인 정보에서 꺼내기 | 대기 | Spring Security는 회원·보안 담당 일정에 맞춤. 그 전까지 헤더 방식은 개발용 |
| 없는 회원번호로 소득 저장 시 FK 위반(ORA-02291)이 500으로 나감 | 대기 | 지금은 `X-Member-Id` 헤더라 아무 숫자나 보낼 수 있어서 생김. Security 연결 뒤엔 로그인한 회원만 오니 사라짐. 그 전에 필요하면 `DataIntegrityViolationException` → 400 처리기 추가 |
| 계산 요청 횟수 제한 없음 (요청마다 `PREDICTION` 행이 쌓임) | 대기 | 로그인 회원 기준으로 제한해야 해서 Security 뒤에 검토. 같은 입력이면 직전 결과 재사용 또는 회원별 1분 N회 제한 |
| 계산 이력 조회 API를 만들 때 `PREDICTION_DETAIL`은 `PREDICTION`과 JOIN해 본인 확인 | 메모 | 아직 조회 API 없음 |
